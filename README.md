## Кратко о приложении

Сервис позволяет владельцу календаря заранее завести несколько типов встреч и принимать записи от гостей без регистрации. Гость выбирает тип встречи, видит свободные слоты на ближайшие 14 календарных дней и бронирует удобное время. Один и тот же интервал нельзя занять дважды, даже если типы встреч разные.

## Роль владельца

В приложении есть один заранее заданный владелец календаря.

### Сценарий владельца

1. Владелец открывает административный раздел приложения.

2. Владелец создаёт тип встречи.

3. Для типа встречи заполняются:
   - название;
   - описание;
   - длительность.

4. После сохранения тип встречи появляется в общем каталоге доступных встреч.

5. Владелец может создать несколько типов встреч с разной длительностью, например 15 минут и 30 минут.

6. Владелец открывает список предстоящих встреч и видит все созданные бронирования независимо от типа встречи.

7. Когда гость записывается на свободный слот, новая запись появляется в списке предстоящих встреч владельца.

## Роль гостя

Гость пользуется сервисом без регистрации и без личного кабинета.

### Сценарий гостя

1. Гость открывает главную страницу сервиса.
2. Гость переходит к списку типов встреч.
3. Гость выбирает подходящий тип встречи по названию, описанию и длительности.
4. После выбора открывается календарь бронирования.
5. Гость видит доступность только в окне ближайших 14 календарных дней.
6. Гость выбирает день из доступного окна.
7. Сервис показывает свободные стартовые слоты для выбранного дня.
8. Длительность каждого занятого интервала определяется выбранным типом встречи.
9. Гость выбирает свободный слот и подтверждает запись.
10. После успешного бронирования слот становится недоступным для повторной записи.

## Обязательные функции

- Просмотр списка типов встреч.
- Создание типа встречи владельцем.
- Хранение для каждого типа встречи: названия, описания и длительности.
- Просмотр календаря доступных слотов для выбранного типа встречи.
- Ограничение окна записи ближайшими 14 календарными днями.
- Создание бронирования гостем без регистрации.
- Просмотр владельцем списка предстоящих встреч всех типов.
- Исключение двойного бронирования одного и того же времени.
- Запрет любых пересечений интервалов, включая частичное наложение между встречами разных типов.
- Корректная обработка одновременных запросов на один слот.

## Ограничения и допущения

- В приложении нет авторизации.
- В приложении нет личных кабинетов.
- В приложении нет интеграции с внешними календарями.
- В приложении только один владелец календаря, он задан заранее.
- Следующая встреча может начинаться ровно в момент окончания предыдущей.
- Начало окна записи, рабочие часы владельца, шаг старта слотов и часовой пояс должны быть зафиксированы позднее в спецификации.
- Данные могут храниться в памяти процесса; если будет выбран этот вариант, в README.md нужно явно указать, что перезапуск сбрасывает записи.

## Требования к API и генерации

- Контракт API должен быть описан через TypeSpec.
- Из TypeSpec должна генерироваться OpenAPI-спецификация.
- Для фронтенда должен генерироваться клиентский SDK из OpenAPI.
- Перед окончательным выбором стека нужно проверить, что для выбранного языка фронтенда существует подходящий генератор клиента.
- Если серверная генерация типов и маршрутов недоступна, бекенд реализуется вручную по контракту и проверяется тестами.
